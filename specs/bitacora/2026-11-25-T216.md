# 2026-11-25 · F2 · T216 · Pool propio para marionetas de enemigo y botín

Agente Opus bajo el orquestador (encargo `ENCARGO-T216.md`), rama `coop/T216`. Carril `[enemigos]`.

Niveles de evidencia (constitución, regla 16): **hipótesis** = leído o razonado; **sintética** = prueba sin el juego;
**compilación** = `clang -c` de objetos sueltos fuera del repositorio. **Nada de esto se ha visto en el juego.**

## ¿Cambia el comportamiento?

**Hoy no.** El cambio queda preparado detrás de una constante local, como pide el paso 2. La ranura "mundo" del pool
(`OA_POOL_WORLD`) es un cambio del coordinador en `oa_core.c`, `oa_frame.c` y `online_actors_internal.h`, que este
carril no puede tocar. Mientras no exista, `POOL_WORLD` vale 0 y las seis llamadas usan el mismo pool que antes
(el del jugador 0): el binario hace lo mismo [hipótesis: es la misma expresión constante].

**Cuando el coordinador defina `OA_POOL_WORLD` en la cabecera interna** (y alargue `oa_g_pool` una fila), este código la
toma sin más cambios. A partir de ahí **sí** cambia el comportamiento: las piezas de las marionetas de enemigo, de sus
armas y de las fuentes de elemento ya no están en el pool del jugador 0. `oa_drop(c, 0, true)` (el jugador 0 se va)
deja de borrarlas, y llenar el pool del jugador 0 deja de borrar una de ellas (`pool_piece`, "full: one goes").

## Qué se hizo

`runtime/oa_enemies.c`, al principio del fichero:

```c
#ifdef OA_POOL_WORLD
#define POOL_WORLD OA_POOL_WORLD
#else
#define POOL_WORLD 0
#endif
_Static_assert(POOL_WORLD >= 0 && POOL_WORLD < (int)(sizeof oa_g_pool / sizeof oa_g_pool[0]), ...);
```

La aserción para la compilación si alguien define `OA_POOL_WORLD` sin alargar `oa_g_pool`. Sin ella el juego
escribiría fuera del array. Comprobado: con `-DOA_POOL_WORLD=ONLINE_MAX` y la cabecera actual, `clang` falla con
*static assertion failed … the world's pool slot is a row of oa_g_pool* [compilación].

Seis llamadas `oa_piece_update(c, 0, …)` pasan a `oa_piece_update(c, POOL_WORLD, …)`:

| Función | Pieza | En el original (`350c5f8`) |
|---|---|---|
| `own_ready` | el enemigo que se crea al pasar a ser nuestro (`"own"`) | `online_actors.c:2231` |
| `elem_update` | fuente de elemento sobre un enemigo (`"element"`) | `:2281` |
| `oa_enemies_host` | fuente de elemento de prueba (`"element test"`, solo con su variable de prueba) | `:2442` |
| `oa_enemies_show` | marioneta `OnlineEnemy_*` de un enemigo del anfitrión (`"host"`) | `:3044` |
| `oa_enemies_show` | arma o escudo de esa marioneta (`"host"`) | `:3058` |
| `oa_enemies_show` | `FireWood` de prueba (`"fire test"`, solo con su variable de prueba) | `:3210` |

`runtime/oa_loot.c` **no cambia**: en el código actual no llama a `oa_piece_update` ni usa `oa_g_pool`. El botín de los
otros (`oa_g_theirs[].p`) se pide con `oa_request` y se toma a mano. Las líneas `:3044` y `:3058` que el contexto de la
tarea llama "botín" son en realidad la marioneta de un enemigo del anfitrión y su arma, y viven en `oa_enemies.c`.

No se añadió ningún estado `static`: solo una macro.

## Petición al coordinador (paso 2 de T216; no lo hace este carril)

Para que T216 tenga efecto en el juego hace falta, en un único cambio del coordinador:

1. `online_actors_internal.h`: `#define OA_POOL_WORLD ONLINE_MAX` (la ranura de nadie) y
   `extern Piece oa_g_pool[ONLINE_MAX + 1][POOL];`. `oa_core.c`: la definición con el mismo tamaño. El tamaño del pool
   por jugador (`POOL`) no cambia.
2. `oa_core.c:oa_pool_update`: recorrer `i <= OA_POOL_WORLD` (o `ONLINE_MAX + 1`). Si no, una pieza del mundo que
   llegue al pool todavía pedida no se toma nunca, y se queda visible donde la cree el juego.
3. `oa_frame.c:forget_all`: dejar huérfanas también las piezas de la fila del mundo (el bucle de `oa_orphan`). El
   `memset` ya cubre todo el array por `sizeof`.
4. `oa_frame.c:frame_out_of_session`: al salir de la sesión, borrar también la fila del mundo (hoy solo se vacía por
   `oa_drop(c, i, true)` de cada jugador). Si no, sus piezas se quedan ocultas bajo el mundo.
5. `RT_ON_RESET` de `oa_core.c`: el `memset(oa_g_pool, 0, sizeof oa_g_pool)` ya cubre la fila nueva. Basta comprobarlo.
6. No hace falta tocar `oa_drop` ni `oa_puppet.c`: nunca reciben `OA_POOL_WORLD` como índice de jugador.

Con eso, `oa_enemies.c` no cambia más: compila tal cual. Este diseño es una propuesta [hipótesis]: lo decide el
coordinador.
